# README Guide

`README.md` should stay short and useful for onboarding.

## Keep In README

- Project purpose.
- Requirements.
- Setup commands.
- Runtime env vars and defaults.
- Google auth setup notes.
- Script list.
- Project structure.
- Links to detailed docs such as API integration, UI system, diagrams, or Codex skills.

## Update README When

- Setup commands, scripts, Node/Expo requirements, env vars, or defaults change.
- Google auth setup changes.
- New detailed docs are created.
- Navigation or structure changes enough that onboarding would be stale.
- Runtime backend URL assumptions change.

## Avoid

- Long API contract tables when `docs/api-integration.md` exists.
- Secret values.
- Future features not represented in code.
