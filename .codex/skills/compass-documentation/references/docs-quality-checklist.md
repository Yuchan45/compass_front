# Documentation Quality Checklist

Before finalizing docs, check:

- Docs match actual code behavior.
- README links newly created docs.
- Script names match `package.json`.
- Env vars match `.env.example` and config.
- API paths and type names match services/types.
- Docs do not expose secrets or imply `EXPO_PUBLIC_*` is private.
- Diagrams use Mermaid and match current flows.
- `CHANGELOG.md` has an `Unreleased` entry for release-note-worthy changes.
- Markdown is concise and scannable.
- Commands and env examples are fenced.
