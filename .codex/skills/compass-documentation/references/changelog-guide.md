# Changelog Guide

Create or update `CHANGELOG.md` for user/developer-visible changes.

## Add Entries For

- New screens, routes, auth flows, or user-visible behavior.
- Breaking setup/env/script changes.
- API integration contract changes.
- Google auth changes.
- Location/privacy changes.
- Important accessibility, performance, or UX fixes.
- New local Codex skills or developer workflow docs.

## Usually Skip

- Pure refactors with no behavior change.
- Formatting-only changes.
- Test-only changes unless they document a fixed bug.

## Format

Use an `Unreleased` section with `Added`, `Changed`, `Fixed`, or `Security` as needed.
